# 게임 에셋 프롬프트 생성 스킬 설계 (아트 디렉션 2단계)

## 의도와 이유

game-build 7단계(에셋)에서 지금은 사람이 `request.md`를 손으로 쓰고, 디자인 문서의 미감 인사이트(명도·채도 위계, 3겹 구도, 재질 언어 등)가 매번 프롬프트에 누락될 위험이 있습니다. 이 스킬은 디자인 문서의 미감 DNA를 **고품질 이미지 생성 프롬프트**로 자동 변환해, 사람이 GPT(ChatGPT 등)에서 생성할 때 스타일 일관성과 품질을 확보하고 반복 비용을 줄입니다. 핵심 가치는 생성 자동화가 아니라 **프롬프트 품질과 일관성**입니다.

## 목표 / 비목표 / 반목표

**목표**
- 디자인 문서를 한 번 읽어 **검토 가능한 스타일 카드**(`style-card.md`)로 증류합니다.
- 에셋 리스트를 받아 에셋별 고품질 프롬프트(공통 스타일 + 개별 + 스토리보드 레퍼런스 지목 + **변형 2~3개** 지시)를 만듭니다.
- 돌려받은 낱장 PNG를 파일명→slot 매칭으로 배치하고, placeholder를 교체합니다.
- GPT에서 사람이 생성하는 전제로 동작합니다(Unity MCP 불필요).

**비목표**
- 자동 이미지 생성(사람이 GPT에서 함). Unity MCP·fal.ai 연동.
- 소리 에셋 생성(별도 문제, FR-019 사람 청취 선정).
- 균일 격자 스프라이트 시트 강제(GPT가 잘 못 그림).

**반목표**
- 스타일 카드 없이 매 배치마다 디자인 문서를 다시 읽어 품질이 들쭉날쭉해지는 것.
- 잠긴 기획 패키지나 디자인 문서를 스킬이 수정하는 것.
- 승인되지 않은 색·규칙을 확정된 것처럼 프롬프트에 박는 것.

## 제약

- **디자인 문서 위치**: 최상위 기준은 `/Users/easyoon/mallang-brain/디자인.md`(30절)와 `/Users/easyoon/mallang-brain/docs/design/title-redesign-2026-11-07/`입니다. 이들은 palolo가 아니라 **mallang-brain 루트(feature/game-planning 워크트리)**에 있습니다. 스킬은 문서 경로를 파라미터로 받고, 문서를 **읽기만** 합니다.
- **승인된 HEX 팔레트 없음**: 디자인.md 5절이 "수치 토큰 미추출"이라고 명시합니다. 색 지정은 정성적("옅은 민트/하늘 앵커 위 따뜻한 난색 캐릭터")으로 하고, 미승인 HEX 후보는 "미승인"으로 분리 표기합니다.
- **에셋 교체 가능 원칙 승계**: 구현은 placeholder로 끝까지 조립되고, 실제 에셋을 끼워도 테스트가 깨지지 않아야 합니다(기존 `asset-request-contract.md` 원칙).
- **GPT 특성**: 균일 격자 시트를 잘 못 그리므로 낱장 생성을 기본으로 합니다.

## 검토한 방식 (approaches)

| 대안 | 구조 | 반박(실패 상황) |
|---|---|---|
| A. 기존 계약 얇게 확장 | manifest에 prompt 필드만 추가, 격자 시트 + split_spritesheet.py 그대로 | GPT가 균일 격자를 못 그림. 변형 2~3개·image 레퍼런스가 격자와 충돌 |
| B. GPT-네이티브 프롬프트 팩(1단계) | 에셋 1장=프롬프트 1개, 매 배치마다 디자인 문서 읽어 프롬프트 생성 | 매번 문서 재독으로 품질 일관성 약함 |
| **C. 2단계 — 스타일 카드 + 프롬프트 컴파일러 (채택)** | ① 문서→검토 가능한 style-card 1회 증류·커밋 ② 카드+리스트→프롬프트 팩·변형·배치 | 선행 구조 큼, 문서 변경 시 카드 갱신 필요 |

**채택: C.** 디자인 기준이 방대하고 권위 문서(디자인.md 30절)에 모여 있어, 한 번 검토 가능한 스타일 카드로 증류하면 배치마다 품질이 흔들리지 않고, 그 카드가 장면 레인 구현(S3 플레이 화면 등)에도 재사용됩니다. 판단(아트 디렉션)과 기계(프롬프트 찍기)를 분리합니다. 사용자 선택(2026-11-08).

## 결정된 설계 (the how)

### 1단계: 스타일 카드 컴파일 (판단 단계, 사람 검토)

- **입력**: 디자인 문서 경로 목록(기본값: 디자인.md + title-redesign-2026-11-07/ + 해당 spec 패키지).
- **처리**: 문서를 읽어 미감 DNA를 증류합니다. 세션(또는 상위 모델)이 수행하는 판단 작업입니다 — 약한 모델에 맡기지 않습니다.
- **출력**: `art-direction/style-card.md`(커밋, 사람 검토용). 섹션:
  1. 공통 스타일 문단(모든 프롬프트 접두사)
  2. 팔레트(정성적 규칙 + 미승인 HEX 후보를 "미승인"으로 분리)
  3. 구도·위계 규칙(3겹 구도, 명도·채도 한 단계 후퇴 + 여백, "한 장면·한 감정", 플레이 가독 순위)
  4. 캐릭터 시트(토끼·카피바라·사막여우·다람쥐: 외형·성격·악기·포인트색·시그니처 순간)
  5. 재질 언어(비눗방울/낡은 종이/젤리)
  6. 금지사항(IP 모사, 각진 눈썹, 사실적 뇌, 유아용 문법 등)
  7. 레퍼런스 이미지 매핑(어떤 승인 이미지/스토리보드 컷을 어떤 에셋의 스타일 레퍼런스로 붙일지)
- **승인**: 사람이 스타일 카드를 검토·승인한 뒤에만 2단계로 갑니다.

### 2단계: 프롬프트 팩 컴파일 (기계 단계)

- **입력**: 승인된 style-card + 에셋 리스트. 리스트 항목: `id`, `name`, `slot`(코드 내 자리), `purpose`(용도), `changeFrequency`, `sceneType`(캐릭터 단독 / 장면 / UI 아이콘 등), 선택 `referenceImage`(스타일 레퍼런스로 붙일 파일).
- **출력**:
  - `asset-requests/prompts.md` — 사람이 GPT에 붙일 에셋별 프롬프트. 각 프롬프트 = 공통 스타일(카드 1절) + 에셋 개별 묘사 + sceneType별 구도 규칙 + 레퍼런스 이미지 지목 + **변형 2~3개 지시**(예: "같은 캐릭터로 포즈/표정만 다른 3안").
  - `asset-requests/manifest.json` — 각 에셋의 기대 파일명 → slot 매핑, 변형 선택 기록 필드.
  - 사람 안내: GPT에서 실행하는 법, 돌려받은 파일 이름 규칙, 변형 중 하나 고르는 법.
- **배치**: 돌려받은 낱장 PNG를 **파일명→slot 매칭**으로 복사(기존 `split_spritesheet.py`를 확장하거나 신규 `place-by-name` 스크립트). slot에 placeholder가 있으면 교체. 결과를 `placed.json`에 기록.
- **변형**: 에셋마다 GPT에 2~3안을 요청하고, 사람이 하나를 골라 slot 파일명으로 저장합니다.

## 확정 사항 (빌더 체크 반영, 2026-11-08)

빌더 체크가 낸 5개 질문을 사용자 결정 2개 + 제 판단 3개로 정리했습니다.

- **스킬 위치 (Q1, 사용자)**: palolo `.claude/skills/`에 **독립 스킬**로 만듭니다. 버전 고정된 plan-handoff 플러그인 캐시는 수정하지 않습니다(업데이트 시 덮어쓰임·공유 인프라). game-build 7단계와의 연결은 스킬 문서 안내로만 남기고, 검증되면 나중에 플러그인 계약으로 승격합니다.
- **작업 범위 (Q4, 사용자)**: 스킬 메커니즘 + **첫 말랑브레인 style-card.md 실제 생성**(디자인.md 30절·title-redesign 문서를 읽어 증류, 사람 승인 대기 상태까지). 완료 검증은 "실제 카드가 사람 검토 가능한 수준"으로 합니다. 2단계(실제 에셋 리스트의 prompts.md 생성)는 카드 승인 후 별도로 돌립니다.
- **격자 vs 낱장 (Q2, 제 판단)**: 새 낱장 흐름은 **독자 manifest**를 쓰고, 기존 격자 `split_spritesheet.py`는 건드리지 않고 "균일 아이콘이 많을 때 선택지"로 남깁니다. 두 흐름을 한 파일로 합치지 않습니다(생성 모델이 다름).
- **style-card 범위·경로 (Q3, 제 판단)**: **프로젝트 전역 1개** `palolo/art-direction/style-card.md`. 디자인 문서는 `/Users/easyoon/mallang-brain`(feature/game-planning 워크트리)에서 **읽기만**, 산출물(style-card·asset-requests·placed.json)은 **palolo에 커밋**.
- **승인 게이트 (Q5, 제 판단)**: 한 스킬 안에서 1단계(카드) 후 멈췄다가 사람 승인 후 2단계 재호출. 스킬을 2개로 쪼개지 않습니다.
