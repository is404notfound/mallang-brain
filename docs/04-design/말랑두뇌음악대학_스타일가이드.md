# 말랑두뇌음악대학 게임 아트 스타일 가이드

> 문서 버전: 1.0  
> 기준일: 2026-09-14  
> 적용 범위: 캐릭터, 캠퍼스 환경, 소품, UI 연계 비주얼, 2D 게임 에셋, 생성형 AI 시안  
> 핵심 문장: **말랑한 뇌 학생들이 실제로 생활하는, 장난감처럼 작고 따뜻한 파스텔 음악대학**

---

## 1. 문서 목적

이 문서는 `말랑두뇌음악대학`의 모든 게임 아트가 제작자와 제작 방식에 관계없이 하나의 세계처럼 보이도록 하는 기준서다. 콘셉트 아트, 캐릭터 스프라이트, 배경, 인터랙션 오브젝트, UI 그래픽, 외주 발주, 생성형 AI 시안 제작에 공통 적용한다.

이 문서의 규칙은 다음 우선순위로 해석한다.

1. 플레이 정보가 즉시 읽혀야 한다.
2. 메인 캐릭터의 고유 실루엣을 지켜야 한다.
3. 캠퍼스 전체가 같은 색·선·형태 언어를 사용해야 한다.
4. 디테일보다 따뜻함, 명료함, 생활감을 우선한다.

규칙에 없는 예외가 필요하면 임의로 확정하지 말고, 시안과 함께 아트 디렉터의 승인을 받는다.

## 2. 비주얼 비전

### 2.1 핵심 인상

- 말랑하고 순한 인상
- 어린 그림책처럼 따뜻하지만 유아용으로만 보이지 않는 디자인
- 현실의 대학을 축소한 듯한 장난감 같은 캠퍼스
- 공부, 휴식, 합주와 연습의 흔적이 자연스럽게 섞인 생활 공간
- 한눈에 캐릭터와 플레이 요소를 찾을 수 있는 단순한 화면

### 2.2 스타일 키워드

`soft` · `rounded` · `cozy` · `playful` · `pastel` · `toy-like campus` · `storybook warmth` · `clear game readability` · `music student life`

### 2.3 디테일 밀도

완성 일러스트의 디테일을 100으로 보았을 때 게임 화면의 권장 밀도는 다음과 같다.

| 요소 | 권장 밀도 | 원칙 |
|---|---:|---|
| 플레이 캐릭터 | 80–90 | 표정과 실루엣은 명확하게, 표면 묘사는 최소화 |
| 인터랙션 오브젝트 | 70–80 | 용도를 한눈에 알아볼 핵심 특징만 강조 |
| 전경 장식 | 50–60 | 플레이를 가리지 않는 범위에서 프레이밍에 사용 |
| 배경 건물·자연물 | 40–60 | 큰 면과 둥근 덩어리 중심 |
| 원경 | 20–40 | 색면과 실루엣만으로 처리 |

배경은 기존 그림책풍 일러스트 대비 **약 60–70%의 디테일**만 남긴다.

## 3. 형태 언어

### 3.1 기본 형태

- 원, 타원, 둥근 사각형, 완만한 곡선을 기본으로 한다.
- 캐릭터와 자연물은 `말랑한 덩어리`, 건물은 `모서리를 둥글린 장난감 블록`처럼 만든다.
- 하나의 오브젝트는 가능하면 큰 덩어리 1–3개와 보조 덩어리 2–5개로 설명한다.
- 좌우가 완전히 대칭인 기계적 형태보다 살짝 눌리거나 기울어진 손맛을 허용한다.
- 날카로운 삼각형은 방향 안내, 위험, 강한 리듬 등 의미가 있을 때만 제한적으로 사용한다.

### 3.2 실루엣 테스트

에셋을 단색으로 채우고 실제 게임 표시 크기의 25%로 축소했을 때도 종류와 방향을 구분할 수 있어야 한다. 내부 선이나 작은 장식이 사라지면 알아볼 수 없는 디자인은 수정한다.

### 3.3 원근과 카메라

- 기본 환경 시점은 **부드러운 3/4 시점** 또는 정면성이 강한 준등각 시점으로 통일한다.
- 극단적인 광각, 사실적인 렌즈 왜곡, 과도한 원근 단축은 사용하지 않는다.
- 건물 수직선은 안정적으로 유지하되 지붕과 간판은 읽기 쉽게 약간 크게 과장할 수 있다.
- 동일 맵 안의 문, 창문, 벤치, 캐릭터 크기는 공통 스케일 시트를 따른다.

## 4. 선 규칙

### 4.1 아웃라인

- 순수 검정이 아닌 **딥 네이비**를 사용한다.
- 외곽선은 둥근 끝과 둥근 연결을 기본으로 한다.
- 선 굵기는 화면 크기에 따라 비례 조정하되, 같은 카메라 레벨에서는 일관되게 유지한다.
- 권장 상대 굵기:
  - 캐릭터 외곽선: `1.00`
  - 캐릭터 내부선: `0.55–0.70`
  - 인터랙션 오브젝트 외곽선: `0.80–0.90`
  - 배경 외곽선: `0.70–0.80`
  - 배경 내부선: `0.40–0.55`
- 즉, 배경선은 캐릭터 외곽선보다 **20–30% 가늘게** 한다.

### 4.2 기준 해상도 예시

`2048 × 2048 px` 마스터 캐릭터 시트에서 캐릭터가 약 `900 px` 높이로 보일 경우:

- 캐릭터 외곽선: `18–24 px`
- 캐릭터 내부선: `10–15 px`
- 배경 주요 외곽선: `13–18 px`

수치는 절대값이 아니라 화면 내 캐릭터 크기를 기준으로 비례 적용한다. 최종 판단은 실제 게임 화면 축소 테스트로 한다.

### 4.3 선 사용 금지

- 순수 검정 외곽선
- 각지고 뾰족한 붓 끝
- 같은 물체 안에서 이유 없이 달라지는 선 굵기
- 재질을 설명하기 위한 촘촘한 해칭
- 배경의 벽돌, 잎맥, 나뭇결을 전부 그리는 방식

### 5.2 사용 비율

기본 환경 한 화면의 권장 면적 비율:

- 크림·베이지 계열: 35–45%
- 세이지·하늘색 계열: 30–40%
- 네이비: 8–12%
- 오렌지·브라운: 8–15%
- 코랄·버터 옐로 포인트: 합계 5–10%

포인트색은 작은 면적에 반복해 리듬감을 만들되, 화면 전체를 코랄이나 노랑으로 채우지 않는다.

### 5.3 명도와 대비

- 메인 캐릭터는 밝은 아이보리·화이트 계열을 유지한다.
- 캐릭터 뒤 배경에는 순백색을 피하고 중간 명도의 베이지, 세이지, 하늘색을 둔다.
- 플레이 가능한 요소는 주변보다 명도 차를 확보하고 네이비 외곽선 또는 얕은 그림자로 분리한다.
- 텍스트와 핵심 아이콘은 색만으로 상태를 전달하지 않는다. 형태, 아이콘, 명도 차를 함께 사용한다.
- UI 텍스트는 실제 적용 단계에서 WCAG 대비 검사를 거친다. 장식용 파스텔색을 작은 본문 텍스트에 직접 사용하지 않는다.

### 5.4 조명과 그림자

- 기본 광원은 화면 좌상단의 부드러운 낮빛이다.
- 그림자는 채도가 낮은 블루그레이 또는 네이비 계열을 낮은 불투명도로 사용한다.
- 캐릭터 접지 그림자는 짧고 둥근 타원형으로 만든다.
- 강한 셀 셰이딩은 피하고 기본색 + 1단 그림자 + 제한적 하이라이트로 마무리한다.
- 검은 그림자, 금속성 과광택, 극적인 역광은 특별 연출 장면 외에는 사용하지 않는다.

## 6. 메인 캐릭터 규칙

### 6.1 고정 아이덴티티

다음 요소는 메인 캐릭터의 필수 조건이다.

- 팔이 없는 말랑한 뇌 형태
- 위아래로 긴 큰 눈 한 쌍
- 작은 볼터치
- 짧고 둥근 두 다리
- 굵은 딥 네이비 외곽선
- 밝은 아이보리 또는 크림색 몸
- 작은 크기에서도 읽히는 단순한 얼굴

위 항목 중 하나라도 빠지면 메인 캐릭터 변형으로 승인하지 않는다.

### 6.2 비율 가이드

캐릭터 전체 높이를 `100`으로 볼 때:

- 뇌 몸통: 높이 `72–78`, 너비 `82–92`
- 눈: 몸통 높이의 `28–38`, 세로가 가로보다 `1.8–2.4배`
- 두 눈 사이 간격: 눈 한 개 너비의 `0.35–0.60`
- 다리: 전체 높이의 `12–18`
- 볼터치: 눈 너비의 `35–55%`, 눈 아래 바깥쪽에 배치
- 바닥 그림자: 캐릭터 너비의 `55–70%`

숫자는 모델 시트 제작용 범위다. 실루엣의 귀여움과 표정 가독성을 위해 범위 안에서 조정할 수 있다.

### 6.3 뇌 주름

- 실제 해부학적 뇌를 묘사하지 않는다.
- 외곽은 큰 둥근 엽 `5–7개` 정도로 단순화한다.
- 내부 주름은 `3–6개`의 짧고 둥근 곡선으로 제한한다.
- 주름은 얼굴을 가르거나 눈 뒤를 복잡하게 통과하지 않는다.
- 공포스럽거나 유기체적인 골, 혈관, 젖은 표면 질감은 금지한다.

### 6.4 얼굴과 감정

- 눈은 캐릭터의 가장 중요한 감정 장치다. 세로형 기본 비율을 유지하면서 눈꺼풀 높이, 기울기, 동공 위치로 감정을 표현한다.
- 입은 작은 점, 짧은 곡선, 작은 타원 범위에서 사용한다.
- 볼터치는 코랄 계열의 부드러운 원 또는 타원으로 표현한다.
- 눈썹은 꼭 필요할 때만 짧은 곡선으로 추가하며, 눈보다 강하게 보이지 않게 한다.
- 치아, 혀, 콧구멍 등 얼굴 요소를 늘려 복잡하게 만들지 않는다.

권장 기본 감정 세트: `neutral`, `happy`, `excited`, `focused`, `surprised`, `sad`, `tired`, `proud`, `confused`.

### 6.5 포즈와 소품 상호작용

- 팔을 새로 그려 행동을 설명하지 않는다.
- 행동은 몸 기울기, 스쿼시·스트레치, 점프, 다리 방향, 얼굴, 소품의 위치로 표현한다.
- 손에 들어야 하는 물건은 몸 옆에 기대거나, 머리 위에 얹거나, 짧은 끈으로 메거나, 전용 받침대 위에 둔다.
- 악기 연주가 필요한 경우에는 세계관에 맞는 페달, 스탠드, 몸통 접촉, 자동 연주 보조 장치 등 팔 없는 연주 방식을 디자인한다.
- 임시로 떠 있는 소품은 작은 모션선이나 접촉 그림자로 관계를 명확히 한다.

### 6.6 애니메이션 원칙

- 기본 애니메이션은 `12 fps` 감각의 키 포즈 중심으로 제작하되 엔진에서는 필요에 따라 보간한다.
- 아이들: 미세한 상하 호흡 + 느린 눈 깜빡임.
- 이동: 짧은 다리의 빠른 스텝 + 몸통의 부드러운 좌우 흔들림.
- 성공: 위로 늘어남 → 가벼운 점프 → 말랑하게 착지.
- 실패: 짧게 수축 → 눈이 아래로 내려감 → 원형으로 회복.
- 변형량은 기본 실루엣의 `10–18%` 안에서 유지한다. 고무처럼 과도하게 늘어나지 않는다.

## 7. NPC 및 캐릭터 변형

- 모든 뇌 캐릭터는 팔 없는 기본 종족 규칙을 공유한다.
- 개성은 몸 색 전체를 바꾸기보다 모자, 안경, 헤드폰, 악기 케이스, 작은 헤어 액세서리, 볼터치 모양으로 표현한다.
- 액세서리는 한 캐릭터당 주요 1개, 보조 1개를 권장한다.
- 실루엣을 가리는 큰 의상, 현실적인 사람 손발, 긴 팔다리는 사용하지 않는다.
- 교수·직원·학생의 구분은 크기 차보다 액세서리와 자세, 색 포인트로 만든다.
- 배경 NPC는 플레이 캐릭터보다 채도와 대비를 낮춰 시선을 빼앗지 않게 한다.

## 8. 캠퍼스 환경 디자인

### 8.1 공통 원칙

- 현실의 대형 캠퍼스가 아니라 뇌 캐릭터 크기에 맞춘 작고 아기자기한 대학으로 만든다.
- 건물은 크림색 큰 면, 따뜻한 오렌지 지붕, 청록·하늘색 창문을 기본 조합으로 한다.
- 창문, 벽돌, 난간은 반복 묘사를 줄이고 큰 그룹 단위로 처리한다.
- 나무의 잎은 낱장 대신 둥근 덩어리 `3–5개`로 표현한다.
- 간판과 출입구는 실제보다 크게 만들어 장소와 이동 경로를 즉시 읽게 한다.
- 음악성은 음표 장식의 반복보다 악기, 악보, 연습 소리의 흔적, 케이스, 스탠드, 공간 사용 방식으로 보여준다.

### 8.2 장소별 기준

#### 본관

- 캠퍼스의 대표 랜드마크.
- 크림색 본체, 따뜻한 오렌지 지붕, 청록색 창문을 사용한다.
- 정문은 크고 둥근 아치 또는 둥근 사각형으로 강조한다.
- 입구 위에 세계관 로고 또는 `MALANG BRAIN MUSIC UNIVERSITY` 사인을 배치한다.
- 현실적인 권위보다 환영받는 장난감 건물의 인상을 준다.

#### 중앙광장

- 탐색 화면과 캠퍼스 허브의 기준 공간.
- 둥근 잔디섬, 큰 안내판, 벤치, 작은 분수 또는 조형물, 미니 야외무대를 배치한다.
- 최소 3개의 주요 동선이 색면과 길 모양만으로 구분되어야 한다.
- 쉬기, 책 읽기, 이어폰 듣기, 가벼운 연습 등 생활형 NPC 행동을 넣는다.
- 장식이 캐릭터의 이동 실루엣과 길을 가리지 않게 한다.

#### 음악관

- 큰 창문 너머로 피아노나 연습 풍경이 보이게 한다.
- 방 문패는 작은 악기 아이콘과 짧은 이름으로 구분한다.
- 권장 사인: `PIANO 101`, `RHYTHM LAB`, `PERCUSSION`, `ENSEMBLE ROOM`.
- 흡음 패널은 촘촘한 기술 설비가 아니라 둥근 컬러 블록으로 단순화한다.

#### 도서관

- 높은 서가보다 캐릭터가 닿을 수 있는 낮고 둥근 서가를 중심으로 한다.
- 악보집, 음악사 책, 듣기 부스, 작은 열람등을 핵심 소품으로 사용한다.
- 차분한 크림·세이지·브라운 비율을 늘리고 포인트색은 줄인다.
- 책등은 개별 글자 대신 색 블록과 1–2개의 상징 아이콘으로 처리한다.

#### 학생회관·카페

- 가장 생활감 있고 따뜻한 공간으로 만든다.
- 커피, 머그, 악보, 헤드폰, 노트북, 게시판, 악기 케이스를 사용한다.
- 목재와 코랄 포인트를 다른 건물보다 조금 더 사용한다.
- 테이블 위 소품은 한 묶음당 `2–4개`로 제한해 잡동사니처럼 보이지 않게 한다.

#### 연습실

- 작은 방에서도 악기 종류와 플레이 목적이 즉시 구분되어야 한다.
- 악기 1종, 스탠드, 의자 또는 페달, 흡음 컬러 블록 정도로 구성한다.
- 피아노실은 정확도, 타악기실은 복합 리듬, 합주실은 기억·협동 플레이와 연결할 수 있다.
- 케이블과 장비는 실제처럼 복잡하게 늘어놓지 않는다.

#### 야외무대

- 중앙광장의 작은 무대와 축제용 큰 무대를 구분한다.
- 둥근 캐노피, 버터 옐로 조명, 코랄 배너를 핵심 언어로 사용한다.
- 고난도·축제 스테이지에서는 포인트색과 관객 밀도를 올리되 플레이 레인은 깨끗하게 유지한다.

#### 기숙사

- 반복 창문 대신 방 그룹 `3–5개`를 큰 단위로 묶는다.
- 작은 발코니, 빨래, 화분, 악기 케이스 스티커 등으로 생활감을 준다.
- 개인 방은 침대, 책상, 수납, 대표 악기 소품 각 1개를 중심으로 구성한다.
- 카페보다 차분하고 개인적인 크림·스카이·세이지 조합을 사용한다.

### 8.3 장소와 게임 모드 연결 예시

| 장소 | 플레이 메타포 | 대표 비주얼 신호 |
|---|---|---|
| 중앙광장 | 기본 박자·튜토리얼 | 넓은 원형 잔디, 작은 무대 |
| 피아노실 | 정확도 | 건반 패턴, 메트로놈 |
| 타악기실 | 복합 리듬 | 둥근 패드, 반복 색 블록 |
| 합주실 | 기억 + 리듬 | 반원형 자리 배치, 여러 악기 |
| 도서관 | 기억·집중 | 악보집, 듣기 부스 |
| 축제 야외무대 | 고난도·최종 공연 | 캐노피, 버터 옐로 조명, 배너 |

## 9. 소품 디자인

### 9.1 소품 분류

- 음악: 피아노, 드럼패드, 메트로놈, 악보, 헤드폰, 튜너, 스탠드, 악기 케이스
- 학업: 책, 노트, 연필, 노트북, 학생증, 게시판
- 휴식: 머그, 쿠션, 벤치, 담요, 작은 간식
- 캠퍼스: 안내판, 깃발, 자전거 거치대, 화분, 조명, 분수
- 기숙사: 알람시계, 낮은 수납장, 침구, 슬리퍼, 세탁 바구니

### 9.2 제작 규칙

- 실제 사물의 특징을 1–3개만 남겨 단순화한다.
- 잡는 손잡이와 버튼은 팔 없는 캐릭터가 사용할 수 있는 크기로 과장한다.
- 인터랙션 가능한 소품은 비인터랙션 소품보다 외곽선이 굵고 명도 대비가 높아야 한다.
- 같은 종류의 소품은 실루엣, 기준 크기, 광원 방향을 공유한다.
- 작은 글자 대신 기호, 색 띠, 악기 아이콘을 사용한다.
- 소품의 얼굴화는 특별한 서사 목적이 있을 때만 허용한다. 모든 물체에 눈과 입을 붙이지 않는다.

## 10. UI와 게임 화면의 시각 우선순위

### 10.1 기본 레이어

낮은 순서에서 높은 순서:

1. 원경 색면
2. 배경 건물·자연물
3. 비인터랙션 소품과 배경 NPC
4. 인터랙션 오브젝트와 이동 경로
5. 플레이 캐릭터·주요 NPC
6. 상황 UI, 리듬 노트, 판정 피드백
7. 일시정지·경고·접근성 UI

### 10.2 화면 유형별 초점

| 화면 | 1순위 | 2순위 | 3순위 |
|---|---|---|---|
| 캠퍼스 탐색 | 플레이 캐릭터 | 이동 목표·인터랙션 | 배경 |
| 대화 | 말하는 캐릭터·대화창 | 선택지 | 배경 |
| 리듬 플레이 | 리듬 노트·판정선 | 캐릭터 반응 | 무대 배경 |
| 보상·성공 | 보상 정보 | 캐릭터 감정 | 장식 효과 |

### 10.3 UI 스타일 연계

- 패널은 둥근 사각형, 캡슐, 말랑한 탭 형태를 사용한다.
- UI 외곽선은 네이비를 쓰되 캐릭터 외곽선보다 같거나 약간 가늘게 한다.
- 선택·성공은 버터 옐로, 친근한 알림은 코랄, 차분한 정보는 스카이, 안정·완료는 세이지를 기본으로 한다.
- 실패는 세계관에 맞는 낮은 채도의 코랄·오렌지를 사용하고 강한 순적색 화면 점멸은 피한다.
- 리듬 노트와 판정선 주변 `최소 1노트 폭`은 배경의 고대비 패턴과 장식을 비운다.
- 파티클은 짧고 둥근 점, 별, 작은 음의 파동 형태로 제한하며 판정 텍스트를 가리지 않는다.
- 배경을 어둡게 처리해야 할 때는 검정 오버레이보다 낮은 채도의 네이비 오버레이를 사용한다.

## 11. 게임 에셋 제작 규칙

### 11.1 제작 단계

1. **브리프:** 용도, 실제 표시 크기, 카메라, 상태 수, 충돌 범위 확인
2. **실루엣:** 단색 썸네일로 형태와 방향 검수
3. **컬러 블록:** 코어 팔레트와 시각 우선순위 검수
4. **라인·표정:** 기준 굵기와 캐릭터 아이덴티티 검수
5. **게임 적용:** 실제 배경과 UI 위에서 축소 가독성 확인
6. **익스포트:** 파일명, 피벗, 패딩, 메타데이터 확인
7. **최종 QA:** 알파, 색공간, 프레임 누락, 아틀라스 번짐 확인

### 11.2 소스와 출력

- 편집 원본은 레이어가 유지되는 포맷(`.psd`, `.ai`, `.afdesign`, `.clip` 등)으로 보관한다.
- 런타임 기본 출력은 투명 배경의 `.png`를 사용한다. 엔진 최적화 포맷은 빌드 파이프라인에서 별도 생성한다.
- 색공간은 `sRGB`로 통일한다.
- 반투명 가장자리에 흰색·검정색 매트가 남지 않게 한다.
- 스프라이트 외곽에는 아틀라스 번짐 방지를 위한 투명 패딩을 둔다.
  - `@1x`: 최소 4 px
  - `@2x`: 최소 8 px
- 원본 레이어와 런타임 출력의 캔버스 중심, 피벗, 프레임 크기를 애니메이션 전체에서 고정한다.

### 11.3 해상도와 스케일

- 프로젝트는 논리 해상도 `@1x`를 먼저 정하고 원본은 최소 `@2x`로 제작한다.
- 같은 카메라 레벨의 모든 환경 에셋은 공통 `pixels per unit` 값을 사용한다.
- 9-slice UI는 늘어나면 안 되는 모서리 범위를 메타데이터에 기록한다.
- 무손실 마스터에서 축소본을 생성한다. 작은 이미지를 확대해 납품하지 않는다.

### 11.4 피벗과 충돌 기준

- 캐릭터: 두 발 사이의 지면 접점 중앙 `bottom-center`
- 이동 가능한 소품: 바닥 접점 중앙
- 벽 부착물: 부착면 중앙
- 파티클: 효과 발생 중심
- UI 아이콘: 시각적 중심
- 실제 그림의 투명 여백이 아니라 **게임 내 접점**을 기준으로 피벗을 잡는다.
- 아트의 둥근 외곽과 충돌 영역을 동일하게 만들지 않는다. 충돌 영역은 단순한 원·캡슐·사각형으로 별도 정의한다.

### 11.5 레이어 분리

배경 씬은 최소한 다음 레이어로 분리한다.

`far_bg` → `building` → `ground` → `back_props` → `characters` → `front_props` → `fx` → `ui`

- 캐릭터가 뒤로 지나갈 수 있는 오브젝트는 하단과 상단 또는 마스크 레이어를 분리한다.
- 인터랙션 표시와 선택 하이라이트는 원본 그림에 굽지 않고 별도 레이어로 둔다.
- 낮·밤, 계절, 이벤트 변화는 가능한 한 공통 베이스 + 교체 레이어 구조로 만든다.

### 11.6 애니메이션 시트

- 모든 프레임은 동일한 캔버스 크기와 피벗을 사용한다.
- 프레임 순서는 파일명 숫자와 메타데이터의 재생 순서가 같아야 한다.
- 반복 애니메이션은 시작과 끝에서 위치가 튀지 않아야 한다.
- 상태 전환에 필요한 진입·이탈 프레임을 별도로 정의한다.
- 프레임 드롭 후에도 눈, 다리, 외곽선이 한 프레임씩 흔들리지 않는지 확인한다.

### 11.7 완료 기준 체크리스트

- [ ] 실제 게임 크기에서 실루엣과 표정이 읽힌다.
- [ ] 캐릭터에 팔이 추가되지 않았다.
- [ ] 외곽선이 딥 네이비이며 기준 굵기를 따른다.
- [ ] 코어 팔레트 또는 승인된 파생색만 사용했다.
- [ ] 배경이 캐릭터·UI보다 강하게 보이지 않는다.
- [ ] 인터랙션 가능 여부가 색 외에도 형태나 표시로 구분된다.
- [ ] 광원과 접지 그림자 방향이 씬과 일치한다.
- [ ] 알파 가장자리와 패딩에 이상이 없다.
- [ ] 피벗, 충돌 기준, 프레임 크기가 올바르다.
- [ ] 파일명과 메타데이터가 규칙에 맞는다.
- [ ] 실제 엔진 화면에서 UI와 겹침을 검수했다.

## 12. 금지사항

### 12.1 캐릭터

- 팔, 사람 손, 긴 다리 추가
- 사실적인 뇌 해부학, 혈관, 젖은 유기체 질감
- 가로로 넓은 일반 카툰 눈으로 변경
- 작은 눈, 과도한 속눈썹, 복잡한 얼굴 요소
- 순수 검정 외곽선 또는 외곽선 없는 반실사 렌더링
- 지나치게 길고 날카로운 실루엣

### 12.2 환경

- 사진 같은 현실적 대학 건축
- 거대한 건물에 캐릭터를 마스코트처럼 얹는 비례
- 낱장 잎, 벽돌, 기왓장, 창문을 모두 묘사하는 과밀한 디테일
- 모든 벽과 소품에 음표를 붙이는 직접적인 음악 장식
- 캐릭터 뒤에 순백색이나 고채도 패턴을 배치하는 구성
- 과도한 광각, 네온 사이버펑크, 무거운 고딕, 차가운 금속 중심 스타일

### 12.3 게임 가독성

- 리듬 노트와 비슷한 색·크기·형태를 배경에 반복 사용
- 판정선 뒤의 강한 줄무늬, 창틀, 케이블
- 중요한 UI를 장식 파티클이나 전경 소품으로 가리기
- 색 하나에만 의존한 성공·실패·선택 상태 표현
- 의미 없는 미세 텍스트와 읽을 수 없는 간판

### 12.4 제작

- 출처와 버전이 없는 파일
- 띄어쓰기, 한글, 특수문자가 섞인 런타임 파일명
- 최종 파일명에 `final`, `진짜최종`, `new`, `copy` 사용
- 서로 다른 피벗과 캔버스 크기를 가진 애니메이션 프레임
- 생성형 AI 결과물을 선 정리와 형태 검수 없이 바로 런타임에 사용

## 13. 파일명 규칙

### 13.1 기본 형식

런타임 에셋 파일명은 영문 소문자와 숫자, 언더스코어만 사용한다.

```text
{type}_{group}_{name}_{state}_{view}_{variant}_{size}.{ext}
```

필요 없는 항목은 생략할 수 있지만 남은 항목의 순서는 유지한다.

### 13.2 토큰 정의

| 항목 | 예시 | 설명 |
|---|---|---|
| `type` | `chr`, `npc`, `env`, `obj`, `ui`, `fx`, `bg` | 에셋 대분류 |
| `group` | `main`, `quad`, `musichall`, `library`, `cafe`, `dorm` | 캐릭터 또는 장소 그룹 |
| `name` | `brain`, `bench`, `piano`, `dialog_panel` | 고유 이름 |
| `state` | `idle`, `walk`, `active`, `disabled`, `night` | 상태·애니메이션 |
| `view` | `front`, `back`, `side`, `threeq` | 방향·카메라 |
| `variant` | `v01`, `blue`, `festival` | 승인된 변형 |
| `size` | `1x`, `2x`, `4x` | 출력 배율 |

### 13.3 예시

```text
chr_main_brain_idle_front_v01_2x.png
chr_main_brain_walk_side_v01_2x.png
npc_musichall_student_focused_threeq_v03_2x.png
env_quad_mainhall_day_v01_2x.png
obj_cafe_headphones_active_v02_2x.png
obj_practice_metronome_idle_v01_2x.png
ui_rhythm_note_success_yellow_2x.png
fx_stage_applause_loop_v01_2x.png
```

### 13.4 프레임과 버전

- 개별 프레임: `_f000`, `_f001`, `_f002`처럼 0부터 시작하는 3자리 숫자를 붙인다.
- 시각 변형은 `_v01`, `_v02`로 관리한다.
- 작업 이력 버전은 소스 관리 또는 DCC 파일 메타데이터로 관리하고 런타임 이름에 날짜나 `final`을 넣지 않는다.
- 의미가 있는 색상 변형만 `blue`, `coral`처럼 이름을 붙인다. 단순 수정본은 색상 변형으로 취급하지 않는다.

## 14. 에셋 메타데이터 규칙

### 14.1 필수 필드

모든 납품 에셋은 동일한 basename의 `.json` 메타데이터 또는 중앙 에셋 데이터베이스 항목을 가져야 한다.

| 필드 | 형식 | 설명 |
|---|---|---|
| `asset_id` | string | 파일 확장자를 제외한 고유 ID |
| `display_name` | string | 사람이 읽는 표시명 |
| `asset_type` | enum | `character`, `npc`, `environment`, `object`, `ui`, `fx` |
| `location` | string | 사용 장소 또는 `global` |
| `state` | string | 상태명 또는 `static` |
| `view` | string | 방향 또는 카메라 |
| `version` | integer | 승인 버전, 1부터 증가 |
| `status` | enum | `wip`, `review`, `approved`, `deprecated` |
| `author` | string | 제작자 또는 제작 시스템 |
| `source_file` | string | 편집 원본 경로 또는 ID |
| `export_file` | string | 런타임 파일 경로 또는 ID |
| `canvas_px` | object | `{width, height}` |
| `pivot_norm` | object | 0–1 정규화 좌표 `{x, y}` |
| `ppu` | number | 프로젝트 기준 pixels per unit |
| `color_space` | string | 기본값 `sRGB` |
| `has_alpha` | boolean | 투명도 포함 여부 |
| `tags` | string[] | 검색·분류 태그 |
| `created_at` | string | ISO 8601 날짜·시간 |
| `updated_at` | string | ISO 8601 날짜·시간 |

### 14.2 조건부 필드

- 애니메이션: `frame_count`, `fps`, `loop`, `frame_order`, `transition_in`, `transition_out`
- 9-slice UI: `slice_border_px`
- 인터랙션 오브젝트: `interaction_type`, `hitbox`, `highlight_style`
- 캐릭터: `emotion`, `costume_id`, `accessory_ids`
- AI 시안 사용: `ai_assisted`, `generation_model`, `prompt_id`, `reference_ids`, `human_cleanup`, `rights_reviewed`
- 지역화 텍스트 포함: `localization_keys`

### 14.3 예시

```json
{
  "asset_id": "chr_main_brain_idle_front_v01_2x",
  "display_name": "메인 뇌 캐릭터 / 기본 대기 / 정면",
  "asset_type": "character",
  "location": "global",
  "state": "idle",
  "view": "front",
  "version": 1,
  "status": "approved",
  "author": "art-team",
  "source_file": "characters/main/chr_main_brain_master.psd",
  "export_file": "runtime/characters/main/chr_main_brain_idle_front_v01_2x.png",
  "canvas_px": { "width": 1024, "height": 1024 },
  "pivot_norm": { "x": 0.5, "y": 0.92 },
  "ppu": 100,
  "color_space": "sRGB",
  "has_alpha": true,
  "frame_count": 8,
  "fps": 12,
  "loop": true,
  "tags": ["brain", "main", "armless", "idle", "front"],
  "ai_assisted": false,
  "rights_reviewed": true,
  "created_at": "2026-09-14T00:00:00+09:00",
  "updated_at": "2026-09-14T00:00:00+09:00"
}
```

### 14.4 관리 원칙

- `asset_id`는 한번 배포한 뒤 재사용하거나 다른 의미로 바꾸지 않는다.
- 수정으로 외형이나 동작 의미가 달라지면 `version`을 올린다.
- `deprecated` 에셋은 새 에셋의 `asset_id`를 대체 항목으로 기록한다.
- AI 보조 여부와 사람의 정리·권리 검수 여부를 반드시 남긴다.
- 프롬프트 전문은 별도 프롬프트 기록에 저장하고 메타데이터에는 `prompt_id`만 둔다.

### 15.8 AI 결과 검수 기준

- 메인 캐릭터에 팔이나 손처럼 보이는 돌기가 없는가?
- 눈이 크고 세로형이며 두 눈의 스타일이 일관적인가?
- 뇌 주름이 단순하고 해부학적으로 보이지 않는가?

- 배경선이 캐릭터보다 얇고 색 대비가 낮은가?

- 기존 작품·브랜드·캐릭터를 모방하거나 식별 가능한 로고가 들어가지 않았는가?
- 최종 사용 전 사람이 선, 색, 투명도, 구조를 정리했는가?

## 16. 빠른 아트 리뷰 기준

리뷰 시 아래 다섯 질문에 모두 `예`라고 답할 수 있어야 한다.

1. 흑백 실루엣만 봐도 메인 캐릭터 또는 장소를 알아볼 수 있는가?
2. 플레이 요소가 배경보다 먼저 보이는가?
3. 팔 없는 뇌 캐릭터의 고유 비율과 세로형 눈이 유지되는가?
4. 따뜻한 파스텔, 딥 네이비 선, 둥근 형태가 일관적인가?
5. 음악 장식이 아니라 음악대학의 생활과 행동이 보이는가?

하나라도 `아니오`라면 디테일을 추가하기 전에 실루엣, 대비, 구성부터 수정한다.

## 17. 한 페이지 요약

### 반드시 지킬 것

- 팔 없는 말랑한 뇌 + 큰 세로형 눈 + 볼터치 + 짧은 다리
- 캐릭터는 굵은 딥 네이비 선, 배경은 20–30% 가는 선
- 크림, 스카이, 세이지, 웜 오렌지, 코랄, 버터 옐로 중심
- 둥근 덩어리, 장난감 같은 작은 캠퍼스, 부드러운 좌상단 광원
- 캐릭터·리듬 UI·인터랙션 요소가 배경보다 먼저 읽히는 구성
- 음악을 음표 장식이 아니라 악기와 학생 생활로 표현

### 피해야 할 것

- 팔·손·긴 다리, 사실적인 뇌, 순수 검정 선
- 사진 같은 건축, 거대한 캠퍼스 비례, 과도한 원근
- 촘촘한 잎·벽돌·케이블·잡동사니
- UI 뒤의 고대비 패턴과 읽을 수 없는 작은 글자
- 생성형 AI 결과물의 무검수 직접 사용
