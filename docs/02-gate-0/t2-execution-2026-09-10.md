# Gate 0 T2 실행 기록 — 2026-09-10

## 현재 판정

**T2 진행 중. Gate 0 통과 아님. Gate 1 미진입.**

시작 시 저장소는 clean 상태였으며 Unity 프로젝트, 환경 테스트, 기존 Android/WebGL 빈 장면 빌드가 있었다. 실제 리듬게임 코드는 없었다. 기존 Gate 0 기간과 정책은 변경하지 않았다. 이 기록은 새 7영업일 기간의 승인을 뜻하지 않는다.

## 이번 구현

- 같은 `SpikeScene`에서 좌우 입력마다 배경색을 바꾸고 짧은 시험음을 요청한다.
- 실제 Input System 마우스·터치·키보드 경로를 사용한다. 화면의 횟수는 점수가 아닌 입력 관찰값이다.
- Android는 가로 장면으로 빌드한다. WebGL은 압축 해제·단일 스레드·전용 시험 템플릿으로 만든다.
- Toss 패키징에서만 설치된 SDK의 가로 방향 호출을 포함한다. 일반 Unity WebGL 출력은 수정하지 않는다.
- SDK 응답 실패·시간 초과는 화면에 표시하고 재시도할 수 있다. 실패했다고 Unity 로더 전체가 멈추지는 않는다.
- 빌드마다 새로운 작업 폴더, Unity 요약 보고서, 로그, 파일 SHA-256을 기록한다. 모든 `SmokeRecord`는 `gateEligible:false`다.

T2 기록은 최종 `BuildManifest`/`RunRecord`가 아니다. 시나리오·판정 정책·외부 측정을 갖춘 T7 기록을 구현했다고 주장하지 않는다. 최종 아트, DSP 판정, 점수·콤보·홀드·군중·콘테스트는 아직 구현하지 않았다.

자동 테스트 6개는 전체 계획의 27개 경로를 완료했다는 뜻이 아니다. Play Mode 테스트는 마우스 상태 이벤트 주입, 연속 탭 화면 변화, pause/focus 조합의 입력 차단, 생성 오디오 샘플의 유효성을 확인한다. 하드웨어 입력 지연과 실제 소리 출력은 측정하지 않았다.

브라우저 시험은 Codex In-app Browser의 1280×720 화면에서 실제 클릭으로 수행했다. Unity 캔버스는 2560×1440으로 표시됐다. 제목·횟수·오디오 요청 상태·플랫폼 문구에 잘림이 없었다. 일반 WebGL 클릭 전후에 수집된 오류·경고는 없었다. Toss 복사본에서는 실제 Toss 환경이 없어 SDK의 `operationalEnvironment` 접근 경고가 발생했고, 재시도 후에도 입력은 동작했다. 이는 실패 격리 확인이며 실제 Toss 통과 근거가 아니다. CLI의 `deploymentId` 출력은 로컬 빌드 식별자이며 콘솔 배포나 시험 QR 생성을 수행하지 않았다.

현재 미리보기: `http://127.0.0.1:8765/2026-09-09T21-43-05-039Z-package-toss/WebGL/`. 서버를 다시 시작하는 방법은 실행 안내를 따른다. 원본 WebGL 템플릿 HTML은 Unity가 치환할 변수가 남아 있어 직접 열어 실행할 수 없다.

## 발견한 문제와 해결

Play Mode 입력 테스트가 `Expected 1, actual 0`으로 실패했다. 처음에는 프레임 확인 순서를 의심했지만 추가 프레임 후에도 재현됐다. 로그에서 가상 마우스가 `enabled=False`, 장면은 `suspended=False`임을 확인했다. 설치된 Input System 소스의 Game View 포커스 규칙과 일치했다.

대안은 입력 처리 메서드를 직접 부르는 단순 테스트와, 테스트 환경에서만 가상 마우스를 플레이어로 라우팅하는 방법이었다. 실제 입력 경로를 유지하는 후자를 선택했다. 설정은 `finally`에서 원복하며 게임 런타임의 포커스 정책은 변경하지 않았다. 수정 후 같은 재현 테스트를 포함한 4개가 통과했다. 초기 실패 기록도 보존했다.

플랫폼 연결은 기존 웹 패키징 도구에 작은 가로 방향 모듈을 추가하는 방법과 Unity SDK 전체 도입을 비교했다. T2에 필요한 호출이 하나이고 기존 구성 재사용이 가능하므로 전자를 선택했다. 공통 C# 런타임에는 Toss SDK를 연결하지 않았다.

| 대안 | 정확성 | 영향 범위 | 유지보수 | 기존 구조 일관성 |
| --- | --- | --- | --- | --- |
| 입력 메서드 직접 호출 시험 | 입력 장치 경로 회귀를 놓침 | 테스트 한정 | 단순하지만 보장 범위 좁음 | 실제 Input System 사용과 차이 |
| 테스트에서 가상 마우스 포커스 설정 복원 — 선택 | 실제 이벤트 처리 경로 검사 | 테스트 설정만 변경 후 원복 | 설치된 Input System 규칙 사용 | 런타임 포커스 처리 유지 |
| 웹 SDK 가로 호출만 번들 — 선택 | T2에 필요한 API 직접 호출 | Toss 복사본에 한정 | 작은 모듈, 기존 CLI 재사용 | 기존 웹 패키징과 일치 |
| Unity SDK 전체 도입 | 더 많은 기능 제공, 현재 검증 범위 동일 | Unity 패키지·브리지까지 확대 | 불필요한 의존성 증가 | 현재 최소 프로젝트 변경 커짐 |

부분 실패 검토: Toss 가로 호출 실패는 상태 표시와 재시도로 끝나며 Unity 로더를 기다리게 하지 않는다. 음원 생성 실패도 입력 횟수·화면 변경을 되돌리지 않는다. 이는 T2 진단 장면의 동작이며 Gate 1에서 요구한 오디오 중단 시 판정 중지·네 박자 복구를 대체하지 않는다. 최종 장식 에셋과 로컬 기록 저장은 아직 런타임에 연결하지 않았다.

Android 보고서의 `sizeBytes`는 Unity 전체 빌드 합계이며 APK 파일 크기와 다르다. 실제 배포 파일 크기는 APK 자체로 확인했다. 기존 성능 테스트 패키지가 빌드 전 자동 생성하는 작은 메타데이터 리소스는 패키지의 빌드 후 정리로 소스에서 사라진다. 이를 사용자 에셋으로 오인해 패키지를 수정하지 않았다.

## 기기와 미확정 조건

- Android 기기: `SM-F956N`, Android 16, 기본 화면 968×2376, density 420. 앱 실행 시 가로 2376×968.
- 처음에는 `unauthorized`로 막혔지만 이후 인증이 완료됐다. APK 설치 `Success`, 앱 실행 `Status: ok`를 확인했다. 사용자에게 실제 탭을 요청한 뒤 저장한 화면에서 왼쪽 3회·오른쪽 2회와 배경색 변화를 확인했다. 자동 터치 주입은 하지 않았다.
- 사용자 확인: “가로화면이고, 좌우 숫자와 배경색이 바뀌어. 짧은 소리도 들려. 토스는 아직 미등록이야.” 첫 탭 소리 여부를 별도로 계측한 것은 아니다.
- 이 기기를 기존 중급 Gate 기준 기기로 임의 지정하지 않았다.
- 기존 구현 계획의 3대 행렬과 개발환경 문서의 중급 1대 운영안 사이 차이를 이번 작업에서 완화하지 않았다. 최종 정책 동결 시 기준 문서와 기기 목록을 일치시켜야 한다.
- `mallang-brain`은 로컬 패키징 후보값이며 등록 확인값이 아니다. 토스 등록 전이므로 전체 T2 완료 처리는 보류한다.
- Android 앱 프로세스 로그에 `AHardwareBuffer` 할당 오류와 dex finalizer `AssertionError`가 있다. 화면·입력·청취는 동작했지만 장기 안정성에 영향이 없다고 단정하지 않는다. 로그를 보존했으며 T2의 나머지 플랫폼 검증 후 후속 기기 안정성 시험에서 재현과 영향을 확인한다.

## 다음 진행 조건

1. Android T2 실행·탭·청취 확인 완료. 이는 전체 Gate 0 Android 측정 통과가 아니다.
2. 토스 콘솔에 테스트 앱을 등록한다. 후보 `mallang-brain`과 다른 appName이면 그 값으로 다시 패키징한다. appName은 등록 후 변경 불가이므로 최종 등록값은 사용자가 결정한다.
3. 콘솔의 앱 출시에서 `.ait`를 업로드하고 테스트하기의 QR로 실제 Toss 앱에서 실행한다. 가로 화면·입력·첫 탭 소리를 확인하고 화면·앱 버전을 기록한다.
4. 두 플랫폼 T2 실제 실행 증거가 갖춰지면 T3~T8을 진행한다.
5. Gate 0 전체 지표와 외부 측정까지 모두 통과한 뒤에만 Gate 1을 시작한다.

토스 공식 안내: [콘솔 앱 등록](https://developers-apps-in-toss.toss.im/prepare/console-workspace.html), [토스앱 QR 테스트](https://developers-apps-in-toss.toss.im/development/test/toss.html). 테스트 앱은 사업자 인증 없이 만들 수 있다. QR 테스트는 로그인된 토스 계정이 워크스페이스 멤버이며 만 19세 이상인 조건이 있다. 이번 작업에서 계정 생성·약관 동의·출시를 대신하지 않았다.
