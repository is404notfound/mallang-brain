# Gate 1 구현 계획: 마림바 콘테스트 첫 재미 검증

작성일: 2026-09-13  
상태: 3스테이지·20명 미니 콘테스트와 Edit/Play Mode 시험 코드 작성, Unity Test Runner·빌드 대기
기준 문서: [제품 비전과 단계별 로드맵](../01-product/product-vision-and-roadmap.md), [Gate 0A 결과](../02-gate-0/gate0a-fixes-2026-09-13.md)

## 1. 이번 Gate가 답할 질문

> 마림바 브레인 콘테스트가 사용자의 자발적인 “한 판 더”를 만드는가?

Gate 0A는 프로토타입을 시작해도 되는 기술 확인이다. Gate 0B의 출시 기준 측정과 Toss 9개 phase 전체 `RunRecord` 확인은 아직 하지 않았다. 이 계획은 그 사실을 통과 처리하거나 기준을 낮추지 않는다.

Gate 1의 외부 사용자 판정은 다음 네 가지다.

| 지표 | 통과선 |
| --- | ---: |
| 첫 스테이지 완료율 | 80% 이상 |
| 첫 실패 뒤 120초 안의 자발적 재도전 | 40% 이상 |
| 첫 세션 5판 도달 | 25% 이상 |
| 콘테스트 활성 플레이타임 | 평균 3분 이상, 25%가 3분 초과 |

## 2. 화면은 어디까지 만드는가

### Gate 1 프로토타입 화면 범위

```text
가로형 브레인 콘테스트 한 화면
│
├─ 4박 카운트인
├─ 중앙 리듬 큐와 마림바 건반
├─ 좌·우 입력 영역과 말렛 반응
├─ Perfect / Good / Miss / 콤보 / 점수
├─ 내 말랑뇌 1명
├─ 20명 합주 군중
│   ├─ 플레이어 1명
│   └─ 연습생이라고 공개한 합성 기록 19명
├─ 스테이지 끝 탈락 연출과 남은 인원
└─ 결과 화면: 도달 스테이지, 정확도, 총점, 다시 참가
```

### 이번 Gate에서 만들지 않는 화면

- 홈, 캠퍼스 탐색, 브레인 연습실, 학점과 학년, 외형 조합
- Supabase 공식 순위, 실제 사용자 백분위, 서버 nonce, 광고, 로그인
- 여러 악기, 2~4학년, 최종 미술 자산, 정식 현지화 전체

화면은 사용자 테스트에 필요한 완성도까지 만든다. 즉, 회색 도형 단계에서 입력 가독성, 내 캐릭터 위치, 군중 탈락, 재도전 흐름을 확인한 뒤 최소한의 음악대학 톤을 입힌다. 최종 아트 자산 제작은 Gate 1 통과 뒤다.

## 3. 구현 순서

| 단위 | 결과물 | 완료 기준 |
| --- | --- | --- |
| 1. 순수 판정 코어 | 차트 검증, 탭·홀드 판정, 점수·콤보, 스테이지 진행 | Edit Mode 전체 경계·상태·결정성 시험 통과 |
| 2. 공용 시간 모듈 | Gate 0 시계 보정 코드를 별도 모듈로 추출 | Gate 0 기존 시험과 160회 보정 시험 통과 |
| 3. 입력·음향 연결 | Input System 입력을 chart microseconds로 변환하고 DSP cue를 예약 | 유효 보정 전 연주 시작 차단, 중단 뒤 재카운트 |
| 4. 콘테스트 화면 | 마림바, 큐, 판정 피드백, 20명 군중, 결과·재시작 | 한 판을 처음부터 결과까지 플레이 가능 |
| 5. Gate 1 계측·사용자 시험 | 런 단위 기록과 진단 20명·검증 20명 | 지표와 95% 신뢰구간으로 Continue/Pivot/Kill 판정 |

첫 변경에서 순수 판정 코어를 먼저 고정했고, 이어서 그 코어를 호출하는 첫 화면을 붙인다. 화면은 점수 규칙을 다시 계산하지 않는다. 이 분리는 화면 수정이 판정 규칙을 망가뜨리지 않게 한다.

## 5. 시간과 시계 보정

- 판정 코어에는 chart 시작 기준의 `int64 microseconds`만 전달한다.
- 점수·콤보·정확도 계산에는 `float`나 `double` 시간을 쓰지 않는다.
- 실제 입력 연결 전에는 160개의 `realtime ↔ DSP` 표본을 모아 중앙값 보정을 만든다.
- 표본 부족, 시계 역행, 5ms 초과 불안정이면 콘테스트를 시작하지 않고 연습용 안내를 보여 준다.
- 화면은 `준비 중` 상태에서 먼저 표본을 모은다. 유효한 보정이 생긴 뒤에만 네 박자 카운트인을 시작한다.
- 시간 변환은 `input_chart_us = round_half_away_from_zero((event_time_s + clock_offset_s - chart_start_dsp_s - user_calibration_s) × 1,000,000)`으로 고정한다.
- `round_half_away_from_zero`는 양수·음수 모두 절반에서 0과 멀어지는 정수로 만든다. 이 함수는 차트 컴파일과 입력 변환에서 하나만 사용한다.
- 앱 background, pause, audio interruption은 Gate 1의 콘테스트 런을 무효화한다. 재개하면 새 네 박자 카운트인과 새 보정을 거친다.

## 6. 차트 계약과 12개 패턴

각 차트는 `chart_id`, `ruleset_version`, 스테이지 목록, 노트 ID, 손, 종류, 목표 시각, 홀드 종료 시각을 가진다. Gate 1 대표 차트는 3스테이지이고, 기존 20스테이지 차트는 회귀 시험용으로 유지한다. 차트는 실행 전에 검증하며 오류가 있으면 기본값으로 조용히 실행하지 않는다.

원본 패턴은 한 박자 480 tick, 한 블록 4박 1,920 tick으로 저장한다. `T`는 tap, `H:endTick`은 hold다. 스테이지 컴파일러는 각 tick을 `round_half_away_from_zero(tick × 60,000,000 / (BPM × 480))` microseconds로 바꾼다. 따라서 음악적 패턴은 BPM이 달라도 같고, 판정용 시간은 정수로 고정된다.

### 차트 검증

- 비어 있는 차트, 중복 노트 ID, 음수 시각, 역순 노트, 잘못된 손·종류 거부
- 홀드 종료는 시작보다 늦어야 함
- 같은 손의 겹치는 홀드 금지
- 스테이지 경계 ±180ms에 노트 배치 금지
- 스테이지 번호, BPM, 통과선, 노트 ID를 모두 검사

## 7. 판정 상태 기계

```text
Tap
unseen → armed → hit(P/G) → closed
              └→ missed → closed

Hold
unseen → armed → holding(start P/G) → released(end P/G/M) → closed
              │                         ├→ cancelled(end M) → closed
              └→ start_missed ────────────────────────────→ closed
```

- 시간 진행은 각 입력 전에 먼저 해당 input timestamp까지 실행한다. 탭 Perfect는 ±60ms, Good은 ±120ms다. +120ms가 지나면 Miss로 닫힌다.
- press가 소비할 후보는 `target - 120ms ≤ input ≤ target + 120ms` 안의 닫히지 않은 같은 손 cue뿐이다. 이 창 밖의 press는 cue를 닫지 않고 ghost miss다.
- 홀드 시작·종료는 각 최대 50점이다. 종료는 -60~+60ms Perfect 50점, -119~-61ms 또는 +61~+180ms Good 35점, 그 밖은 Miss 0점이다.
- 시작이 유효하지 않은 홀드는 종료 점수를 주지 않는다.
- Stage 1의 잘못된 손은 안내만 표시하고 큐·점수·콤보를 바꾸지 않는다.
- Stage 2 이후 잘못된 손은 가장 가까운 해당 큐를 Miss로 닫고 만회할 수 없다.
- 여러 유효 후보가 가능한 입력은 절대 offset이 가장 작은 닫히지 않은 큐를 고른다. 동률이면 이른 cue, 그다음 낮은 note ID다.
- 같은 손의 추가 press는 `ghost_miss`다. 점수 30점을 깎고 콤보를 0으로 만든다.
- 활성 홀드가 없는 release는 점수와 콤보를 바꾸지 않고 `unmatched_release` 진단만 남긴다.
- touch-cancel은 활성 홀드의 남은 종료 판정을 Miss로 닫는다. 이미 닫힌 노트는 다시 계산하지 않는다.

## 8. 점수, 콤보, 스테이지 결과

### 기본 점수

- 탭: Perfect 100, Good 70, Miss 0
- 홀드: 시작과 종료 각각 Perfect 50, Good 35, Miss 0
- `base_score`는 판정 점수의 합이다.
- `accuracy_score = max(0, base_score - ghost_miss × 30)`이다.
- `accuracy = accuracy_score / note_max_score × 100`이며 0~100으로 제한한다.

### 콤보 배율

콤보는 공식 총점과 동점 순서에 영향을 준다. 정확도와 스테이지 통과선에는 영향을 주지 않는다.

| 성공 뒤 콤보 | 배율 |
| ---: | ---: |
| 0~9 | 1.00 |
| 10~19 | 1.10 |
| 20~39 | 1.25 |
| 40 이상 | 1.50 |

- 탭 Perfect·Good, 또는 시작과 종료 모두 유효한 홀드 한 개가 콤보를 1 올린다.
- 그 노트의 성공 뒤 콤보로 배율을 정하고, 해당 노트의 기본 점수에만 적용한다.
- Miss, Stage 2 이상 잘못된 손, 홀드 종료 Miss, ghost miss는 콤보를 0으로 만든다.
- 배율은 `100/100`, `110/100`, `125/100`, `150/100`의 정수 분수다. 노트가 성공으로 닫힐 때 `round_half_away_from_zero(base_note_score × numerator / 100)`을 한 번만 더한다.
- `rank_score = max(0, combo_adjusted_score - ghost_miss × 30)`이다.
- 스테이지 통과는 `accuracy`가 해당 단계의 기준 이상일 때다. 실패 즉시 런을 끝낸다.
- 20개 스테이지를 모두 통과하면 `completion=true`, `last_completed_stage=20`, `fail_stage=21`이다.

## 9. 성능과 실패 처리

- RhythmCore의 입력·시간 진행 경로는 호출마다 새 목록, 배열, 문자열을 만들지 않는다. 호출자 버퍼 또는 값 형식 이벤트를 사용한다.
- 화면 단계의 20개 군중 슬롯은 시작 전에 준비하고 재사용한다. 연주 중 `Instantiate`, `Destroy`를 사용하지 않는다.
- 가까운 참가자 23명은 기본 성능 프로필에서 개별 표시하고, 먼 76명은 묶음 표시한다. 저성능 프로필에서는 가까운 참가자를 11명으로 줄인다. 24명 이하가 되면 남은 생존자를 자세히 표시한다.
- 상세 캐릭터 수를 줄여도 화면의 묶음 표시와 점수판 숫자는 항상 같은 실제 생존 인원을 뜻해야 한다.
- 군중 애니메이션을 불러오지 못하면 정지 군중과 남은 인원 숫자를, 점수판 연출이 실패하면 기본 숫자 UI를 보여 준다.
- 군중·VFX·점수판 연출이 실패해도 판정, 점수, 스테이지 진행과 재도전은 멈추지 않는다.
- 차트 검증 실패, 시간 역행, 유효 보정 실패는 런을 시작하거나 계속하지 않고 이유를 기록한다.
- 기록 저장이 실패하면 플레이 결과 화면은 보여 주되 `기록 저장 실패`를 표시한다. 재도전을 막지 않는다.

## 10. 시험 계획

첫 구현에는 약 46개의 Edit Mode 시험을 포함한다.

## 11. Gate 1 사용자 시험과 계측

### 최소 이벤트

- `app_ready`, `run_start`, `run_state`, `run_end`, `crowd_drop`, `result_action`
- 모든 이벤트에는 익명 설치 ID, session ID, build, platform, language, cohort, event timestamp를 넣는다.
- `run_start`에는 run ID, previous run ID, session 내 run index, mode, chart/ruleset, 시작 시각을 넣는다.
- `run_end`에는 run ID, end reason, 종료 시각, stage, duration, accuracy, score, judgement 분포, 기술 오류 여부를 넣는다.
- `result_action`에는 해당 run ID, 선택 행동, 행동 시각을 넣어 다음 `run_start`와 연결한다.
- 매 노트는 원격으로 보내지 않고 런 종료 집계만 기록한다.
- 첫 프로토타입은 로컬 JSON 기록 sink를 사용한다. 외부 분석 연결은 사용자 동의와 계정 준비 뒤 별도 어댑터로 붙인다.

### 참가자와 판정

- 18세 이상, 이전 cohort에 참여하지 않은 사용자만 Gate 1 적격으로 집계한다.
- 진단 20명 → 한 가지 가설만 수정 → 독립 검증 20명 순서다.
- 경계값 ±5%p 또는 신호 충돌 때만 예비 20명을 사용한다.
- 첫 입력 전 crash·설치 실패·오디오 불능은 행동 지표에서 제외하되 기술 실패로 별도 기록한다.
- 사용자 테스트 동의, 녹화 목적, 보관 기간을 먼저 알린다. 얼굴·음성은 기본 녹화에서 제외한다.
