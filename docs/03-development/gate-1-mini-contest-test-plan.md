# Gate 1 미니 브레인 콘테스트 시험 계획

작성일: 2026-09-25  
대상 브랜치: `main`  
관련 계획: `docs/03-development/gate-1-mini-contest-plan.md`

## 영향을 받는 화면

- `Gate1ContestPrototype` — 조율부터 결과와 재도전까지 전체 흐름을 확인한다.
- 16:9, 20:9, 4:3 가로 화면 — 군중 20칸, 리듬 큐, 결과 버튼이 safe area 안에 있는지 확인한다.

## 꼭 확인할 상호작용

- 첫 입력으로 콘테스트를 시작하고 네 박자 뒤 Stage 1이 시작된다.
- 왼쪽·오른쪽 탭이 한 번씩만 판정된다.
- 홀드를 누르고 떼면 시작과 끝이 각각 판정된다.
- OS touch cancel은 홀드 Miss가 되고 런은 계속된다.
- Stage 1과 2를 통과하면 탈락 연출 뒤 다음 카운트가 시작된다.
- 실패하거나 Stage 3을 끝내면 결과가 유지된다.
- `다시 참가`를 누르면 같은 연습생 기록 19명과 새 런을 시작한다.

## 경계와 오류 상황

- 입력 없음: Stage 1 실패.
- 정확도 통과선 바로 아래·정확히 경계·바로 위.
- 3스테이지 완주: `last_completed_stage=3`, `fail_stage=4`.
- 기존 20스테이지 완주: `last_completed_stage=20`, `fail_stage=21`.
- 잘못된 roster: 순위만 숨기고 플레이와 결과·재도전 유지.
- 같은 성능 기록: 공동 순위.
- tap release의 `UnmatchedRelease`: 직전 Perfect/Good 표시 유지.
- pause/focus 상실: 현재 런을 성공으로 저장하지 않고 재조율.
- 로그 저장 실패: 결과와 재도전 유지.
- 오디오 실패: 기술 오류로 표시하고 Gate 1 행동 지표에서 제외.

## 핵심 전체 흐름

```text
앱 시작
→ 조율
→ 연습생 기록 안내
→ Stage 1
→ 20명에서 12명
→ Stage 2
→ 12명에서 6명
→ Stage 3
→ 6명에서 3명
→ 20명 중 순위 결과
→ 다시 참가
→ 같은 roster 확인
```

## 자동 시험

- Edit Mode: 3스테이지 차트, sentinel, roster 검증, 순위, 동점, fallback, 기존 20스테이지 회귀.
- Play Mode: 상태 전환, 원본 입력 timestamp, press/release/cancel, 탈락 숫자, 결과 유지, 재도전, pause/focus.
- 빌드: 현재 커밋의 Android와 WebGL 결과를 각각 기록한다.

## 자동 시험으로 대신할 수 없는 확인

- 마림바가 따뜻하고 타격감 있게 들리는지 헤드폰과 스피커에서 듣는다.
- 카운트·타격·탈락음이 겹칠 때 찢어지거나 너무 큰 소리가 없는지 듣는다.
- 실제 장비 입력 지연과 화면 반응은 별도 측정으로 남긴다.
- 실제 사용자 Gate 1 지표는 외부 테스트 전까지 미측정으로 둔다.
